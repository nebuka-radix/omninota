# 机上検討まとめ：MonacoEditor共通コンポーネントと説明文編集

本書は机上検討で整理した仕様を記録するもの。
この内容だけをもって実装開始・依存追加・DB変更を指示するものではない。
確定事項と、検討中の案・未確定事項を区別する。

────────────────────────────────────────
1. 共通コンポーネント
────────────────────────────────────────

名称：
- MonacoEditor
- 当初の表記「MonacoEdotor」は、上記へ統一する案。

目的：
- Syntax選択、WordWrap、テキスト編集などを共通コンポーネントにまとめる。
- 各画面・モーダルへ簡単に配置できるようにする。

使用するライブラリ・仕組み：
- monaco-editor：テキスト編集とシンタックスハイライト
- monaco-prettier：MonacoとPrettierの連携
- prettier：Markdown表などの整形
- Monacoの言語定義・Monarch：言語ごとの色分け
- Prismやhighlight.jsを重ねる構成にはしない。

ライブラリの導入バージョン、Worker構成、
Gherkin言語定義の提供状況などは実装時に確認する。

────────────────────────────────────────
2. 表示構成
────────────────────────────────────────

1行目：
- Syntaxラベル
- Syntaxプルダウン
  - Markdown
  - Plain Text
  - Gherkin
- WordWrapチェックボックス
  - default = false

2行目：
- Monacoによる複数行テキスト編集領域
- デフォルトの表示行数：4行
- フォントサイズ：8pt
- 行番号：表示
- 右下に高さ変更ハンドル

構成例：

┌─────────────────────────────────────────────┐
│ Syntax [ Markdown ▾ ]   ☐ WordWrap           │
├─────────────────────────────────────────────┤
│ 1 │                                         │
│ 2 │           テキスト編集領域               │
│ 3 │                                         │
│ 4 │                                       ◢ │
└─────────────────────────────────────────────┘

補完案：
- 横幅は配置先に合わせる。
- ミニマップは非表示にする。
- 内容が表示領域を超えた場合は、エディタ内部でスクロールする。

────────────────────────────────────────
3. プロパティ
────────────────────────────────────────

指定されたプロパティ：

TextRows as integer
- default = 4
- テキスト編集領域の初期の高さを表示行数で指定する。
- 入力できる最大行数を制限するものではない。
- Syntax・WordWrapの操作行は高さ計算に含めない。

IndentSize as integer
- default = 2
- 正の整数。
- タブの表示幅と、スペースによるインデント幅を指定する。

本文・状態連携用のプロパティ案：

- value: string
- onChange(value: string)
- syntax: 'markdown' | 'plaintext' | 'gherkin'
- onSyntaxChange(syntax)
- wordWrap?: boolean
- onWordWrapChange?(wordWrap: boolean)
- readOnly?: boolean
- ariaLabel?: string

配置例：

<MonacoEditor
  value={description}
  onChange={setDescription}
  syntax={syntax}
  onSyntaxChange={setSyntax}
  TextRows={4}
  IndentSize={2}
  wordWrap={wordWrap}
  onWordWrapChange={setWordWrap}
/>

上記はAPIの設計案。
プロパティ名の最終的な命名規則は実装前に整理する。

────────────────────────────────────────
4. WordWrap
────────────────────────────────────────

確定事項：
- 1行目にチェックボックスを配置する。
- default = false。
- false：長い行を折り返さない。
- true：編集領域の幅で折り返す。
- 表示上の折り返しであり、本文へ改行を追加しない。

整理した仕様案：
- WordWrapを切り替えても、編集領域の高さを勝手に変えない。
- 本文やUndo履歴をリセットしない。

────────────────────────────────────────
5. 編集領域の高さ変更
────────────────────────────────────────

確定事項：
- 編集領域の右下をドラッグして高さを変更可能にする。

整理した仕様案：
- 上下方向の高さだけを変更する。
- 横幅は配置先に合わせる。
- Syntax・WordWrapの操作行はリサイズ対象にしない。
- TextRowsは初期の高さを決める。
- ユーザーが変更した後は、その高さを優先する。
- 入力やWordWrap切り替えで初期高さへ戻さない。

未確定：
- 最小高さ・最大高さ
- 次回表示・次回起動時に変更した高さを復元するか
- 高さを保存する場合の保存単位

────────────────────────────────────────
6. 交互の行背景色
────────────────────────────────────────

確定事項：
- テキスト編集領域の行背景色を交互に変える。

整理した仕様案：
- 奇数行と偶数行で、控えめに異なる背景色を使う。
- ライト／ダークテーマに合わせる。
- 選択範囲・カーソル行・ハイライトとの判別性を維持する。
- 行番号に対応する論理行を色分けの単位とする。
- WordWrapで折り返した部分は、元の行と同じ背景色にする。

未確定：
- 具体的なカラーコード

────────────────────────────────────────
7. インデント・Tab
────────────────────────────────────────

確定事項：
- Tabキーではタブ文字ではなくスペースを挿入する。
- インデント幅はIndentSizeに従う。
- default = 2。

整理した仕様案：
- Tab：次のインデント位置までスペースを挿入する。
- Shift+Tab：インデントを1段階戻す。
- 複数行選択時は、まとめてインデント／アウトデントする。
- 既存本文に含まれるタブ文字を、自動でスペースへ変換しない。
- IndentSize変更だけでは本文を書き換えない。

────────────────────────────────────────
8. Undo／Redo
────────────────────────────────────────

確定事項：
- テキスト編集はUndoに対応する。

整理した仕様案：
- Undo：⌘Z
- Redo：⇧⌘Z
- 入力・削除・貼り付け・自動挿入・インデント変更を対象にする。
- Prettierによる表の自動整形も取り消せるようにする。
- 自動整形は1回分の編集として扱う。
- 整形をUndoした直後に、同じ整形を自動再実行しない。
- Syntax・WordWrap・高さ変更で本文のUndo履歴を失わない。
- Syntax・WordWrap・高さ自体の変更は、本文のUndo対象に含めない。

────────────────────────────────────────
9. シンタックスハイライト
────────────────────────────────────────

確定事項：
- 選択中のSyntaxに応じてハイライトする。

Markdown：
- 見出し、強調、リンク、コード、表の区切りなどを色分けする。

Plain Text：
- 構文による色分けなし。

Gherkin：
- キーワードは英語のみ認識する。
- シナリオ名、ステップ本文、コメントなどは日本語入力可能。
- 日本語キーワードは認識対象にしない。

対象キーワード例：
- Feature
- Rule
- Background
- Scenario
- Scenario Outline
- Examples
- Given
- When
- Then
- And
- But
- *

Gherkinの追加配色：
- タグ：シアン
  例：@smoke、@regression
- コメント：オリーブ
  例：# コメント

リンク：
- 文字色：paleturquoise（#AFEEEE）
- 下線あり
- Markdownリンクや、リンクとして認識するURLを対象にする。

整理した仕様案：
- Syntax変更で本文やUndo履歴を書き換えない。
- ハイライトと交互の行背景色を共存させる。
- ライト／ダークテーマとの判別性を確認する。

未確定：
- シアン・オリーブの具体的なカラーコード
- リンククリック時の遷移・外部ブラウザー起動方法
- Markdownリンクのどの範囲にリンク装飾を適用するかの詳細

10. Markdown表の自動整形
────────────────────────────────────────

確定事項：
- Syntax = Markdownの場合、
  「|」を使用した表の列幅をPrettierで自動調整する。
- 各列の内容に合わせて空白を補い、区切りを揃える。

例：

整形前：
| Name        | Status |
|-------------|--------|
| A           | Open   |
| Longer name | Done   |

整形後：
| Name        | Status |
|-------------|--------|
| A           | Open   |
| Longer name | Done   |

整理した仕様案：
- 有効なMarkdown表を対象にする。
- 単に「|」を含む文章は対象にしない。
- 表以外の文章を、この自動調整で変更しない。
- WordWrap設定は変更しない。
- 本文への編集として扱い、Undo／Redoに対応する。
- IME変換中には整形しない。
- 古い整形結果で新しい入力を上書きしない。

自動整形タイミングの案：
- 編集後、カーソルが表の外へ移ったとき
- または、エディタからフォーカスが外れたとき

未確定：
- 上記タイミングの最終決定
- 表部分だけを安全に整形する具体的な実装方法

────────────────────────────────────────
11. Markdownの箇条書き・チェックリスト入力支援
────────────────────────────────────────

Syntax = Markdownの場合、
Markdown All in Oneのような入力支援を設ける方針。

対象：
- 箇条書き：-、*、+
- チェックリスト：- [ ]、- [x]
- 番号付きリスト：1.、1)
- 独自の番号付き形式：(1)

Enterでの継続：

- 項目A
↓ Enter
- 項目A
-

チェックリスト：

- [x] 項目A
↓ Enter
- [x] 項目A
- [ ]

番号付き：

1. 項目A
↓ Enter
1. 項目A
2.

独自形式：

(1) 項目A
↓ Enter
(1) 項目A
(2)

確定事項：
- (1)形式も自動で通し番号を振る。
- 箇条書き記号の前にあるインデントを、次の行へ引き継ぐ。
- スペース・タブの並びそのものを引き継ぐ。
- 貼り付けなどで既存本文にタブがある場合、
  継続行にも同じタブを引き継ぐ。
- 「Tabキーで新規に挿入する場合はスペース」とは分けて扱う。

整理した仕様案：
- 同じ記号・階層を維持する。
- 完了済みチェックリストの次も、未チェックで追加する。
- 番号は桁が増えても継続する。
- 途中に項目を追加した場合、同じ階層の後続番号を振り直す。
- ネストしたリストは階層ごとに番号を管理する。
- 空の項目でEnterを押すと、記号を削除してリスト入力を終了する。
- リスト行頭のTab／Shift+Tabで階層を変更する。
- 記号幅も考慮し、継続行の本文開始位置を揃える。
- 本文中の「(数字)」は、自動採番の対象にしない。
- コードフェンス内ではリスト記号を自動継続しない。
- IME変換確定のEnterでは継続処理を行わない。
- 自動挿入・番号更新はUndo／Redoに対応する。
- Plain Text・Gherkinでは、この支援を無効にする。
- 表のセル移動にTabを使う機能は、今回は追加しない。

注意：
- (1)形式はCommonMark標準の番号付きリストではない。
- アプリ独自の入力支援として扱う。
- 将来プレビューでリストとして描画する場合は、別途対応を検討する。

12. コンポーネントと配置先の責務
────────────────────────────────────────

MonacoEditor側：
- Syntax選択
- WordWrap
- 本文編集
- TextRowsによる初期高さ
- 高さ変更
- 行番号・文字サイズ・行背景
- ハイライト
- Markdown入力支援
- Prettier整形
- Undo／Redo

配置先の画面・モーダル側：
- 本文と設定値の保持
- 対象レコードとの関連付け
- DB保存
- 保存キュー
- DraftGuard
- 画面遷移・終了時の保護

整理した方針：
- 共通コンポーネントから直接DB保存しない。
- 本文変更を配置先へ通知する。
- Syntaxなども外部と連携できるようにする。

13. プロジェクト説明文
────────────────────────────────────────

確定事項：
- Project画面の右サイドバーに、
  そのプロジェクトの説明文を編集する領域を設ける。
- エディタには共通MonacoEditorを使用する。
- プロジェクトのレコードに説明文を保存する。

カラム案：
- 既存の説明用カラムがあれば利用する。
- なければprojects.descriptionを追加する。
- 実テーブル名・既存schemaは実装時に確認する。

配置案：

右サイドバー：プロジェクト詳細
┌─────────────────────────────────────┐
│ ステータス・完了操作など             │
│                                     │
│ 説明                                │
│ Syntax [ Markdown ▾ ] ☐ WordWrap     │
│ ┌─────────────────────────────────┐ │
│ │ 1 │                             │ │
│ │ 2 │      プロジェクト説明        │ │
│ │ 3 │                             │ │
│ │ 4 │                           ◢ │ │
│ └─────────────────────────────────┘ │
└─────────────────────────────────────┘

設定案：
- 初期Syntax：Markdown
- TextRows：4
- IndentSize：2
- WordWrap：false
- 右下から高さ変更可能
- 共通エディタの機能を適用する
- 既存のステータス・完了操作を維持する

保存に関する案：
- 既存の保存キュー・DraftGuardへ統合する。
- Project切り替えや画面遷移で入力を失わない。
- 別Projectへ誤保存しない。

14. マイルストン説明文
────────────────────────────────────────

確定事項：
- マイルストンにも説明文を設ける。
- Project画面のマイルストンカードへ吹き出しアイコンを配置する。
- クリックするとMonacoEditorを配置したモーダルを表示する。
- 説明文はそのマイルストンのレコードへ保存する。

カラム案：
- 既存の説明用カラムがあれば利用する。
- なければmilestones.descriptionを追加する。

配置・操作案：
- 吹き出しアイコンはカード見出し部分に置く。
- モーダルにマイルストン名を表示する。
- カードのDnD、名前変更、削除メニューと操作を分離する。
- IDで対象を識別し、同名Milestoneでも誤保存しない。
- 閉じた後は元のアイコンへフォーカスを戻す。

エディタ設定案：
- 初期Syntax：Markdown
- TextRows：4
- IndentSize：2
- WordWrap：false
- 高さ変更・Undo／Redoなど共通機能を適用する。

────────────────────────────────────────
15. マイルストンの吹き出しアイコン
────────────────────────────────────────

確定事項：
- 説明文が空の場合は半透明にする。
- 説明文がある場合は通常の不透明表示にする。
- 半透明でもクリック可能とする。
- 未入力の表示であり、無効状態ではない。

空として扱う状態：
- NULL／未設定
- 空文字
- 空白文字のみ

整理した仕様案：
- 保存・説明削除後に表示を即時反映する。
- ツールチップを状態に応じて切り替える。
  - 空：説明を追加
  - 内容あり：説明を編集
- アクセシブル名を付ける。

未確定：
- 半透明の具体的な不透明度
