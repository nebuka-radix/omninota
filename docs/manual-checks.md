# キーボード操作と手動確認の手順

自動テスト・スクリプト操作では確認できない項目を、人が実際に操作して確認するための手順。
確認した結果（日付・環境・OK/NG・気づいた点）は、この表の右側に追記していく。

## 準備

```zsh
cd ~/git/gtd
export PATH="$HOME/.nvm/versions/node/v24.12.0/bin:$PATH"   # Node 24（nvm）
DIR=$(mktemp -d /tmp/gtd-manual-XXXXXX)
GTD_DEV_USER_DATA_DIR=$DIR npm run dev   # 検証用の一時DB（開発用・通常利用のDBは使わない）
```

- 一時DBは空なので、確認に必要なタスクをInboxで数件登録してから始める。
- VoiceOver: ⌘F5 で開始・終了。

## キーボード操作の一覧

| 場所 | キー | 動作 |
|---|---|---|
| タスク一覧 | ↑ / ↓ | 現在行（枠線）を移動。選択は変えない |
| タスク一覧 | Home / End、PageUp / PageDown | 先頭・末尾、10行ずつ移動。未表示の行はスクロールして表示 |
| タスク一覧 | Enter | 現在行を選択し、詳細パネルに表示 |
| タスク一覧 | Space | 現在行の完了／未完了を切り替え（選択は変えない） |
| 追加欄・タイトル欄 | Enter | 登録・保存（日本語IMEの変換確定のEnterでは実行しない） |
| ペインの境界線 | ← / →、Home / End | 幅の変更。ダブルクリックで既定の幅 |
| 確認ダイアログ | Tab / Enter / Esc | ボタンの移動・決定・キャンセル（一覧へは伝わらない） |

## 確認項目

| # | 操作 | 期待する結果 | 結果 |
|---|---|---|---|
| 1 | 一覧をTabでフォーカスし、↓で移動 | 現在行に枠線。選択行（背景色）とは区別できる | |
| 2 | 現在行でSpace | 完了になり取り消し線。「未完了」表示では行が消え、次の行が現在行になる | |
| 3 | 「すべて」で同じ行にSpaceを2回 | 完了 → 未完了に戻る。行は残る | |
| 4 | 1件だけ表示される検索で、その行をSpace | 一覧が空になってもフォーカスが一覧に残る（Tabで次へ進める） | |
| 5 | 検索欄でSpace・↓・Enterを押す | 入力に使われ、一覧の行は動かない | |
| 6 | 詳細でタイトルを編集したまま、一覧で同じ行にSpace | 確認ダイアログ（保存/破棄/キャンセル）。ダイアログ中の↓で一覧が動かない | |
| 7 | 詳細のタイトル欄で日本語IMEを使い、変換確定のEnter | 保存されない。もう一度Enterで保存 | |
| 8 | タイトル編集中に⌘Q →「保存して終了」 | 保存されてから終了。再起動後に新しいタイトル | |
| 9 | タイトルを空白にして⌘Q →「保存して終了」 | 終了しない。「タイトルを入力してください」が表示され、入力欄にフォーカス | |
| 10 | タイトル編集中に⌘Q →「保存せずに終了」 | 終了。再起動後は元のタイトル（ペイン幅など他の設定は保存されている） | |
| 11 | タイトル編集中に⌘Q →「キャンセル」 | 終了しない。編集を続けられる | |
| 12 | タイトル編集中にウィンドウの閉じるボタン（または⌘W） | 「保存して閉じる/保存せずに閉じる/キャンセル」。閉じてもアプリはDockに残る | |
| 13 | ⌘Qを素早く何度も押す | ダイアログ・保存は1回だけ | |
| 14 | 境界線にフォーカスして → を押し、すぐ⌘Q | 再起動後に変更後の幅（通常終了の場合） | |
| 15 | 「視差効果を減らす」をオン | 画面切り替えのフェードがなくなる | |
| 16 | VoiceOverで一覧を操作 | 行が「タイトル、完了／未完了、作成日時」と読まれ、Spaceで結果が読み上げられる | |
| 17 | Projectsでプロジェクトを作成（日本語IMEで入力し、変換確定のEnter） | 変換確定では作成されない。もう一度Enterで作成し、そのプロジェクトが開く | |
| 18 | 見出しの鉛筆ボタン → 名前を変えてEnter | 保存され、サイドバーの順序も更新される | |
| 19 | 名前の編集中に別のプロジェクト・Inbox・設定をクリック | 「プロジェクト名の変更を保存しますか？」。キャンセルで移動しない | |
| 20 | タスクのタイトル編集中にProjectsへ | 「タスクのタイトルの変更を…」の確認 | |
| 21 | 名前の編集中に⌘Q →「保存して終了／保存せずに終了／キャンセル」 | ダイアログの文言が「プロジェクト名に未保存の変更があります」。それぞれ期待どおり | |
| 22 | プロジェクトを開いたまま終了・再起動 | 同じプロジェクトが開く | |
| 23 | 名前の編集中に別のプロジェクトをクリック → 確認ダイアログで「キャンセル」 | 閉じるアニメーション中も文言が「プロジェクト名の…」のまま（「タスクのタイトル」に切り替わらない） | |
| 24 | プロジェクトを開いたまま終了し、`#/settings` などを指定せずに再起動 / 最後の画面のプロジェクトが無い状態で再起動 | 同じプロジェクトが開く / Projects（未選択）が開く | |

## フェーズ5.1: スクリプト操作による確認結果（2026-11-10）

人の操作ではなく、CDP（Chrome DevTools Protocol）での入力・クリックと、Mainプロセスのインスペクターで確認した。
検証用の一時DB（`GTD_DEV_USER_DATA_DIR`）・開発ビルドで行い、通常利用DB・開発DBは使っていない。
終了時のネイティブダイアログは `dialog.showMessageBox` の応答を差し替え、保存失敗・取得失敗はIPCハンドラーを差し替えて再現した。

| 項目 | 結果 |
|---|---|
| 作成（Enter）→ 作成したプロジェクトが開く、同名の作成、一覧の順序 | OK |
| 名前変更（Enter）、前後空白だけの同じ名前は更新しない、空白のみ・201文字は保存できない（理由と入力を保持） | OK |
| 名前の編集中に別プロジェクト・Inboxへ → 確認（キャンセル・破棄・保存） | OK |
| タスクのタイトル編集中にProjectsへ → 「タスクのタイトル」の確認 | OK |
| 名前変更の保存失敗 → 入力と理由を保持。確認で「保存」を選んでも失敗なら移動しない | OK |
| 保存失敗の状態で終了 →「保存して終了」→ 終了せず中断（ダイアログは重ねない） | OK |
| プロジェクト名の「保存して終了／保存せずに終了／キャンセル」、ダイアログの文言 | OK（応答の差し替え） |
| 再起動後の復元、明示ルート（`#/settings`）の優先、起動だけでは設定を書き込まない | OK |
| 保存済みのプロジェクトが存在しない → /projects、存在しない・不正なID、一覧の取得失敗の表示 | OK |
| Inboxの追加・編集（Enter）・完了／未完了（Space） | OK |
| 確認ダイアログを閉じる途中の文言（23） | 修正後、閉じた後に誤った文言が残らないことのみ確認。アニメーション中は未確認 |
| 日本語IMEの変換確定のEnter（17）、フォーカス表示、実ボタン操作 | 未確認（人の操作が必要） |
| パッケージ版での実行 | 未確認（.appの生成のみ） |
