# 実装計画

## フェーズ0: 現状確認と技術確定

- リポジトリ、既存コード、package.jsonを確認する。
- technology-decisions.mdの未確定事項を確認する。
- React/MUI/Lucide/Motionの構成方針を確認する。
- ビルド・配布・DB・ペイン配置の技術を確定する。
- アプリ名とIDを決める。
- バージョンと互換性を確認する。

完了条件:
- 確定事項と保留事項を文書に記録する。
- 未承認の選定を承認済みと扱わない。

## フェーズ1: 起動可能な土台

- Electron、Preload、Reactを構築する。
- TypeScript strictを設定する。
- Router、QueryのProviderを設定する。
- MUIテーマとMotionの共通設定を用意する。
- 開発起動、型チェック、ビルドを確認する。
- 導入: React、MUI、lucide-react、Motion、Query、Router、Zod、electron-vite。
- 用途別API app.getInfo、IPC送信元検証、開発用userDataの分離を実装する。
- Inbox / Settingsの仮画面と、画面領域を識別できる簡単な枠を用意する。
- 対象外: SQLite、Table / Virtual、ペインのリサイズ、インストーラー、署名。

完了条件:
- ElectronウィンドウにReact画面が表示される。
- Rendererに不要なNode.js権限がない。
- 指示書が初期化によって失われていない。

## フェーズ2: SQLiteの縦断検証

- 接続、初期マイグレーション、タスクテーブルを実装する。
- 入力検証、Service、Repository、IPCを実装する。
- 1件登録・取得する。
- 終了・再起動後に復元する。
- パッケージ化したアプリでも確認する。
- 導入: better-sqlite3、Drizzle ORM / Drizzle Kit、electron-builder。
- better-sqlite3の同梱バイナリと再ビルド要否を、採用版の実体と公式情報で確認する。

完了条件:
- 実DBの保存先が明示されている。
- 開発用と通常利用用のデータが混ざらない。
- ネイティブモジュールとマイグレーションが配布後も動く。

フェーズ2で持ち越した課題:
- Electron起動フラグの制限（Fuses。リモートデバッグ・inspect引数の無効化など）
- マイグレーション失敗時のダイアログ表示の実機確認
- 人の操作による日本語IME入力の確認
- 開発ツールの依存に含まれるnpm auditの指摘（drizzle-kit、electron-builder）
- E2Eテストツールの選定

## フェーズ3: AppShell

- トップバー
- アクティビティバー
- 左サイドバー
- メインパネル
- 右詳細パネル
- ステータスバー
- 導入: react-resizable-panels（左右ペインの幅調整。Dockviewは使わない）。

完了条件:
- ダークテーマとアイコンの見た目が統一される。
- ペイン調整と必要なUI状態の保存が動作する。
- キーボード操作とフォーカス表示を確認する。

フェーズ3の実装内容:
- 画面枠を TopBar / ActivityBar / Sidebar / MainPanel / DetailPanel / StatusBar に分割した。
- Workspace状態（左右の幅・詳細パネル表示・最後の画面）を app_settings に保存する（0001マイグレーション）。
- 詳細パネルは選択中タスクを読み取り専用で表示する（編集・完了・削除は未実装）。

フェーズ3.1（ペイン幅の保存ルールと終了時の保存）:
- 希望幅と実寸を分け、ユーザーが直接操作したペインの希望幅だけを保存するようにした。
- 境界線のダブルクリックを「対象ペインを既定幅に戻して保存」に統一した。
- 通常の終了・ウィンドウを閉じる前に、確定済みの最新値の保存完了を待つようにした（待機上限3秒）。
- DBマイグレーションは追加していない（保存形式は変更なし）。

フェーズ3で持ち越した課題:
- 人の操作による確認（マウスでのリサイズ、ダブルクリック、キーボード操作、フォーカス表示、Reduced Motion、IME入力、
  閉じるボタン・⌘W・⌘Q、保存失敗・応答なし時のダイアログの各ボタン）
- 実際のウィンドウを最小幅まで縮めた時の確認（検証は表示幅の上書きで代替した）
- フェーズ2からの持ち越し課題（Fuses、マイグレーション失敗ダイアログ、npm audit、E2Eツール）

## フェーズ4: Inbox

- タスク追加、一覧、詳細、編集、完了を実装する。
- Queryのキーと更新方法を統一する。
- TableとVirtualを組み合わせる（この時点で導入する）。
- ローディング・空・失敗状態を表示する。
- IME変換中のEnter誤登録を防ぐ。
- 控えめなアニメーションを追加する。

完了条件:
- 追加から完了、再起動まで一連の操作が動く。
- 失敗時に成功したような表示をしない。
- 大量行でスクロールと選択を確認する。
- Reduced Motion設定に対応する。

フェーズ4の実装内容:
- tasks.completed_at を追加（0002マイグレーション）。完了状態はcompleted_atから導出する。
- tasks.updateTitle / tasks.setCompleted（目的の状態を指定）を追加。存在しないIDは NOT_FOUND。
- Inbox一覧を Query（全件）＋ Table v9（絞り込み・ソート）＋ Virtual（固定行高）で実装。
- 詳細パネルでタイトルの明示保存・完了／未完了の切り替え。未保存の編集は確認してから破棄する。
- 検証用に、未パッケージ時だけ有効な環境変数 GTD_DEV_USER_DATA_DIR を追加（ユーザーのDBを使わずに大量データを確認するため）。

フェーズ4で持ち越した課題:
- 人の操作による確認（実際のIME、キーボード操作、フォーカス表示、Reduced Motion、終了時ダイアログのボタン）
- スクリーンリーダーでの一覧・確認ダイアログの読み上げ確認
- 可変行高（長いタイトルの折り返し）
- フェーズ3.1からの持ち越し（キーボードで幅を変えた直後の終了、Rendererの window.close() が保存確認を通らないこと）

フェーズ4.1（Inboxの操作性と未保存データ保護）:
- 一覧から Space で完了／未完了を切り替え（listboxを維持。操作方法の表示・読み上げ名・ライブリージョン）。
- 完了で現在行が消えた時・空一覧になった時のフォーカス管理。aria-activedescendant は描画済みの行だけを参照。
- 終了フローに「保存して終了／保存せずに終了／キャンセル」を追加（draftAction: check / save / discard）。
- 終了前の確認で1フレーム待ち、キーボードで変えた直後のペイン幅も保存する。
- 手動確認の手順: docs/manual-checks.md

フェーズ4.1で持ち越した課題:
- Rendererの window.close() 経路（docs/architecture.md「保証できない経路」に修正案）
- VoiceOverでの読み上げ確認、人の実操作による確認全般
- 終了時のネイティブダイアログの実ボタン操作（検証は応答の差し替えで行った）

## テスト方針

Unit:
- GTD業務ルール
- 入力検証
- 日付と日時の扱い

Integration:
- RepositoryのCRUD
- マイグレーション
- トランザクション
- バックアップ・復元
- IPC契約

E2E:
- 起動
- タスク追加・編集・完了
- 画面遷移
- 再起動後の復元
- ペイン・タブ状態
- パッケージ化後の保存

Unit・Integrationはvitest（ホストNode.js、`npm test`）で実行する。
E2Eのテストツールは未選定。採用前に実行環境とElectron対応を確認する。
