# 実装計画

## フェーズ0: 現状確認と技術確定

- リポジトリ、既存コード、package.jsonを確認する。
- technology-decisions.mdの未確定事項を確認する。
- React/MUI/Lucide/Motionの構成方針を確認する。
- ビルド・配布・DB・ペイン配置の技術を確定する。
- アプリ名とIDを決める。
- バージョンと互換性を確認する。

完了条件:
- 確定事項と保留事項を文書に記録する。
- 未承認の選定を承認済みと扱わない。

## フェーズ1: 起動可能な土台

- Electron、Preload、Reactを構築する。
- TypeScript strictを設定する。
- Router、QueryのProviderを設定する。
- MUIテーマとMotionの共通設定を用意する。
- 開発起動、型チェック、ビルドを確認する。

完了条件:
- ElectronウィンドウにReact画面が表示される。
- Rendererに不要なNode.js権限がない。
- 指示書が初期化によって失われていない。

## フェーズ2: SQLiteの縦断検証

- 接続、初期マイグレーション、タスクテーブルを実装する。
- 入力検証、Service、Repository、IPCを実装する。
- 1件登録・取得する。
- 終了・再起動後に復元する。
- パッケージ化したアプリでも確認する。

完了条件:
- 実DBの保存先が明示されている。
- 開発用と通常利用用のデータが混ざらない。
- ネイティブモジュールとマイグレーションが配布後も動く。

## フェーズ3: AppShell

- トップバー
- アクティビティバー
- 左サイドバー
- メインパネル
- 右詳細パネル
- ステータスバー

完了条件:
- ダークテーマとアイコンの見た目が統一される。
- ペイン調整と必要なUI状態の保存が動作する。
- キーボード操作とフォーカス表示を確認する。

## フェーズ4: Inbox

- タスク追加、一覧、詳細、編集、完了を実装する。
- Queryのキーと更新方法を統一する。
- TableとVirtualを組み合わせる。
- ローディング・空・失敗状態を表示する。
- IME変換中のEnter誤登録を防ぐ。
- 控えめなアニメーションを追加する。

完了条件:
- 追加から完了、再起動まで一連の操作が動く。
- 失敗時に成功したような表示をしない。
- 大量行でスクロールと選択を確認する。
- Reduced Motion設定に対応する。

## フェーズ5: GTD機能の拡張

以下は詳細仕様を確認してから実装する。

- プロジェクト
- Next Actions
- 待機中
- いつか／たぶん
- タグ、期限
- 完了履歴
- 週次レビュー
- 検索

## フェーズ6: データ保護・配布

- バックアップと復元
- スキーマ更新時の移行確認
- 異常終了時の扱い
- ログとエラー表示
- 必要なCPU向けの配布検証
- 必要に応じて署名・公証
