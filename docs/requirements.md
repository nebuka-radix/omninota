# 要件

## 目的

macOS向けに、VS Code風の操作感を持つGTDツールを開発する。
ローカルSQLiteファイルにデータを保存する。

## 明示された要件

- macOS、VS Code、Electron、TypeScriptを使用する。
- Claude Codeで開発を進める。
- データはSQLiteファイルへ永続保存する。
- TanStack Query、Table、Virtual、Routerを採用する。

## ここまでの構成案

- ReactをUI基盤とする。
- MUIをUIコンポーネントに使用する。
- Lucideをアイコンに使用する。
- Motion for Reactをアニメーションに使用する。
- Main、Preload、Rendererを分離する。
- 単一リポジトリ、単一package.jsonから始める。

上記は会話上の構成方針。
厳密な承認状況はtechnology-decisions.mdを参照する。

## 画面構成案

- トップバー
- アクティビティバー
- 左サイドバー
- メインパネル
- 右詳細パネル
- ステータスバー

基本はダークテーマとし、カードよりリストとペインを優先する。

## GTD機能の候補

初期の縦断実装:
- Inboxへのタスク追加
- タスク一覧
- タスク詳細の表示・編集
- タスク完了
- 再起動後のデータ復元

後続の機能候補:
- プロジェクト
- Next Actions
- 待機中
- いつか／たぶん
- 期限・タグ
- 完了履歴
- 週次レビュー
- 検索・絞り込み

後続機能の詳細ルールは、実装前に決める。

## プロジェクト（フェーズ5で承認した方針）

承認した全体方針（5.1〜5.3）:
- プロジェクトの作成・一覧・選択・名前の編集・完了・完了の取り消し。項目は id / name / createdAt / updatedAt / completedAt。
- 名前: 前後空白を除去、空白のみは禁止、最大200文字（タスクのタイトルとは別の定数）、同名を許可。
- 一覧の順序: 未完了 → 完了、各区分は日本語の名前順（同名は作成日時・IDの順）。
- タスクは最大1つのプロジェクトに所属（所属なしも可）。所属の変更・解除ができ、所属変更でID・作成日時・完了日時は変えない。
- Inbox: 初期版の暫定定義として「プロジェクトに属さないタスク」（5.2で適用）。「未所属」と「未整理」が本来同じ意味だとは扱わない。
  Next Actionsなどの分類を導入する時に改めて設計する。全タスクを横断する画面は今回追加しない。
- プロジェクトの完了: 未完了のタスクがあれば拒否し、理由と件数を示す。子タスクの一括完了はしない。
  完了の取り消しでタスクの状態は変えない（5.3）。
- 完了済みプロジェクト: 新規タスクの追加・移動・所属タスクの完了取り消しは拒否、外への移動・タイトル編集・名前編集は許可。
  整合性はMain側で保証する（5.2・5.3）。
- 名前の編集は見出しで行い、明示保存・取り消し・既存の未保存確認と「保存して終了」に統合する。
- プロジェクトの切り替え時: 検索はリセット、状態フィルターは未完了、ソートは維持、タスク選択は解除（未保存の確認の後。5.2）。
- タスクの所属変更は詳細パネルで選んだら即時保存（タイトルのドラフトは上書きしない。5.2）。
- 初期版の対象外: 階層、複数所属、削除、手動並べ替え、マイルストーン、期限、タグ、繰り返し、Next Actions、待機中、
  いつか／たぶん、週次レビュー、タブ管理。

上記は承認済みの方針で、すべてが実装済みという意味ではない（実装状況は下記と docs/implementation-plan.md）。

フェーズ5.1で実装した範囲: projectsテーブル、作成・一覧・選択・名前変更、Projects画面（/projects・/projects/<ID>）、
最後の画面の復元（lastRouteの拡張）、未保存確認の一般化（タスク名・プロジェクト名）、プロジェクト名の「保存して終了」。

フェーズ5.2で実装した範囲: タスクの所属（tasks.project_id）、プロジェクトを指定した作成、所属の変更・解除（詳細パネルで即時保存）、
プロジェクト内のタスク一覧、Inboxを「プロジェクトに属さないタスク」に変更、一覧と追加欄の共有、
完了済みプロジェクトへの追加・移動の拒否（Main側）と、完了済みからの移動の許可、プロジェクト切り替え時の画面状態。

5.2の時点で未実装（承認済みの将来方針）:
- プロジェクトの完了・取り消しの操作（API・ボタン）、未完了タスクがある場合の完了の拒否、所属タスクの完了取り消しの拒否 → 5.3
  （完了済みプロジェクトに対する5.2の規則は実装済みだが、完了済みのプロジェクトを作る操作はまだない）

5.2での扱い:
- プロジェクトの切り替え時、タスクの選択は解除する。InboxとProjectsの間の移動でも、別の範囲を開いたら解除する（同じ範囲へ戻れば維持）。

未保存の扱い（5.1）: プロジェクト名の編集ドラフトは保護対象（画面遷移・別の編集の開始・終了時に確認）。
作成欄の未送信の入力は、タスクの追加欄と同じく保護対象外。

## UI状態の保存案

- 選択中のアクティビティ
- 左右ペインの幅
- 詳細パネルの表示状態
- 開いているタブ
- アクティブタブ

保存は業務データと分離する。
ドラッグ中の毎フレームのDB書き込みは避ける。

## 初期版の対象外

明示的な追加依頼がない限り、以下を前提にしない。

- クラウド同期
- 複数端末同期
- アカウント・ログイン
- チーム共有
- プラグイン機構
- VS Code拡張API互換
- モバイル版
- カレンダーや外部サービスとの連携

## 要確認事項

- アプリ名、アプリID
- ペイン配置ライブラリ
- タブ分割・ドラッグ移動の必要性
- DBドライバーとORM
- タスク階層・プロジェクト階層
- Next Actionsの判定条件
- 期限と開始日、繰り返しの仕様
- バックアップの保存先と保持数
- 配布対象CPU、署名・公証の必要性
