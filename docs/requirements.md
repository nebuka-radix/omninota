# 要件

## 目的

macOS向けに、VS Code風の操作感を持つGTDツールを開発する。
ローカルSQLiteファイルにデータを保存する。

## 明示された要件

- macOS、VS Code、Electron、TypeScriptを使用する。
- Claude Codeで開発を進める。
- データはSQLiteファイルへ永続保存する。
- TanStack Query、Table、Virtual、Routerを採用する。

## ここまでの構成案

- ReactをUI基盤とする。
- MUIをUIコンポーネントに使用する。
- Lucideをアイコンに使用する。
- Motion for Reactをアニメーションに使用する。
- Main、Preload、Rendererを分離する。
- 単一リポジトリ、単一package.jsonから始める。

上記は会話上の構成方針。
厳密な承認状況はtechnology-decisions.mdを参照する。

## 画面構成案

- トップバー
- アクティビティバー
- 左サイドバー
- メインパネル
- 右詳細パネル
- ステータスバー

基本はダークテーマとし、カードよりリストとペインを優先する。

## プロジェクト（フェーズ5で承認した方針）

承認した全体方針（5.1〜5.3）:
- プロジェクトの作成・一覧・選択・名前の編集・完了・完了の取り消し。項目は id / name / createdAt / updatedAt / completedAt。
- 名前: 前後空白を除去、空白のみは禁止、最大200文字（タスクのタイトルとは別の定数）、同名を許可。
- 一覧の順序: 未完了 → 完了、各区分は日本語の名前順（同名は作成日時・IDの順）。
- タスクは最大1つのプロジェクトに所属（所属なしも可）。所属の変更・解除ができ、所属変更でID・作成日時・完了日時は変えない。
- Inbox: 初期版の暫定定義として「プロジェクトに属さないタスク」（5.2で適用）。「未所属」と「未整理」が本来同じ意味だとは扱わない。
  Next Actionsなどの分類を導入する時に改めて設計する。全タスクを横断する画面は今回追加しない。
- プロジェクトの完了: 未完了のタスクがあれば拒否し、理由と件数を示す。子タスクの一括完了はしない。
  完了の取り消しでタスクの状態は変えない（5.3）。
- 完了済みプロジェクト: 新規タスクの追加・移動・所属タスクの完了取り消しは拒否、外への移動・タイトル編集・名前編集は許可。
  整合性はMain側で保証する（5.2・5.3）。
- 名前の編集は見出しで行い、明示保存・取り消し・既存の未保存確認と「保存して終了」に統合する。
- プロジェクトの切り替え時: 検索はリセット、状態フィルターは未完了、ソートは維持、タスク選択は解除（未保存の確認の後。5.2）。
- タスクの所属変更は詳細パネルで選んだら即時保存（タイトルのドラフトは上書きしない。5.2）。
- 初期版の対象外: 階層、複数所属、削除、手動並べ替え、マイルストーン、期限、タグ、繰り返し、Next Actions、待機中、
  いつか／たぶん、週次レビュー、タブ管理。

上記は承認済みの方針で、すべてが実装済みという意味ではない（実装状況は下記と docs/implementation-plan.md）。

フェーズ5.1で実装した範囲: projectsテーブル、作成・一覧・選択・名前変更、Projects画面（/projects・/projects/<ID>）、
最後の画面の復元（lastRouteの拡張）、未保存確認の一般化（タスク名・プロジェクト名）、プロジェクト名の「保存して終了」。

フェーズ5.2で実装した範囲: タスクの所属（tasks.project_id）、プロジェクトを指定した作成、所属の変更・解除（詳細パネルで即時保存）、
プロジェクト内のタスク一覧、Inboxを「プロジェクトに属さないタスク」に変更、一覧と追加欄の共有、
完了済みプロジェクトへの追加・移動の拒否（Main側）と、完了済みからの移動の許可、プロジェクト切り替え時の画面状態。

フェーズ5.3で実装した範囲: プロジェクトの完了・完了の取り消し（projects.setCompleted）、未完了タスクがある場合の完了の拒否
（理由と件数の表示、「未完了のタスクを表示」の導線）、所属タスクの完了取り消しの拒否、Sidebarの「未完了／完了済み」の区分表示、
完了操作と未保存の編集（DraftGuard）・進行中の保存との整合。子タスクの一括完了・自動的なプロジェクト完了・削除は行わない。

5.3で決めた表示の規則:
- プロジェクトを開いた時（切り替えた時）の状態フィルター: 未完了のプロジェクトは「未完了」、完了済みのプロジェクトは「完了」。
  （5.2の「切り替え時は未完了」を、このように調整した）
- 同じ画面のまま完了・取り消しをしても、表示中の状態フィルター・検索は変えない（一覧が突然空になる・入れ替わることを避ける）。
  完了しても選択中のプロジェクトの画面に留まり、Sidebarの区分だけが変わる。
- 完了が拒否された時の「未完了のタスクを表示」: 同じプロジェクトのまま、状態を「未完了」にし、検索で隠れる未完了タスクがあれば検索を消し、
  一覧の先頭へ戻す（未保存の編集は変えない）。

5.2での扱い:
- プロジェクトの切り替え時、タスクの選択は解除する。InboxとProjectsの間の移動でも、別の範囲を開いたら解除する（同じ範囲へ戻れば維持）。

未保存の扱い（5.1）: プロジェクト名の編集ドラフトは保護対象（画面遷移・別の編集の開始・終了時に確認）。
作成欄の未送信の入力は、タスクの追加欄と同じく保護対象外（フェーズ5.5で作成欄を廃止。新規プロジェクトの名前は入力済みなら保護対象）。

## マイルストンとInboxからの紐付け（フェーズ5.4。2026-11-10 ユーザーの指示）

最低限の機能で実際に使える状態にすることを優先する方針に変更した（フェーズ5の受け入れ確認はユーザー判断により今回は省略）。

データの関係: Project └ Milestone └ Task。タスクはプロジェクトだけに所属でき、マイルストンの指定は任意（フェーズ5.6で B は廃止。下記）。
- A. projectId = null, milestoneId = null → Inbox
- B. projectId あり, milestoneId = null → プロジェクト内の「マイルストン未設定」
- C. projectId あり, milestoneId あり → そのプロジェクトのマイルストン
- milestoneId だけ（projectId = null）と、他プロジェクトのマイルストンとの組み合わせは禁止。

マイルストン（今回の範囲）: 登録・一覧・名前変更。名前は前後空白を除去、空白のみ禁止、最大200文字（専用の定数）、同名可。
表示順は作成日時・IDの昇順。完了済みプロジェクトへの登録は拒否、既存マイルストンの名前変更は可。
今回は実装しない: 完了状態、期限、削除、階層、手動並べ替え、ドラッグ＆ドロップ、所属プロジェクトの付け替え。

画面:
- 幅広のナビゲーション（Inbox / Projects（登録欄・未完了と完了済みの区分。5.8で区分は廃止）/ 設定）。旧アクティビティバーと独立したサイドバーは削除。
- Inboxの各行の「紐付け」（キーボードは M）から、プロジェクト → 「このプロジェクトに紐付け」またはマイルストン を選び、1回で保存する。

- 詳細パネルから所属（プロジェクト・マイルストン）の変更・解除ができる。

## 削除と所属ルールの変更（フェーズ5.6。2026-11-10 ユーザーの指示）

以前の提案のうち「最後のマイルストンの削除禁止」「マイルストン削除時の別マイルストンへのタスク移動」「プロジェクト削除時のInboxへのタスク移動」
「既存の未設定タスクの初期マイルストンへの移行」は採用しない。

所属ルール（5.4の B「プロジェクトだけ」を廃止）:
- A. projectId = null, milestoneId = null → Inbox
- C. projectId あり, milestoneId あり（そのプロジェクトのマイルストン）→ プロジェクトのタスク
- マイルストン0件のプロジェクトも存在できるが、タスクの追加・紐付けはできない。「マイルストン未設定」のカード・選択肢・追加先、
  紐付けメニューの「このプロジェクトに紐付け」は削除。完了済みプロジェクトへの追加・移動の禁止は維持。
- 新規プロジェクトは名前の保存時に「新しいマイルストン」（通常のマイルストン。名前変更・削除可）を同じトランザクションで作る。
  最後のマイルストンを削除しても自動で作り直さない。
- 移行（0006）: 移行時点の「プロジェクトあり・マイルストンなし」のタスクを、完了・未完了を問わず一度だけ物理削除する（事前のバックアップが必要。docs/database.md）。

削除:
- タスク: Inbox・カードの行のメニュー（キーボード可）から、対象を示す確認の後に物理削除。プロジェクトを自動で完了しない。
- マイルストン: カード見出しのメニューから。DB上の所属タスクが0件なら確認なしで削除（最後の1件も可）。タスクがあれば、名前・件数と
  「タスクは削除されず、画面に表示されなくなる」ことを確認してから、所属タスクの milestoneId を null にして非表示にし（projectId は維持）、マイルストンを物理削除。
- プロジェクト: 右の詳細パネルから（未完了・完了済みとも）。名前・マイルストン数・タスク総数と「配下は残るが表示されなくなる」ことを確認してから、
  配下のマイルストン（projectId = null）・タスク（projectId・milestoneId = null、既に非表示のものも含む）を非表示にし、プロジェクトを物理削除。
  Inboxへは戻さない。成功後は Inbox へ移る。
- 削除由来の非表示データ（tasks.hidden_at・milestones.projectId = null）は、Inbox・プロジェクト画面・選択肢・紐付けメニュー・検索・件数・
  完了判定に含めない。通常のInboxタスク（「Inboxへ戻す」で戻したものを含む）は非表示にしない。復元機能は今回追加しない。

## Inboxの一括操作・インライン編集・並べ替え・終了処理（フェーズ5.9。2026-11-11 ユーザーの指示）

- Inboxの右サイドバー: 既存の右パネルで「紐付け先」（未完了の Project > Milestone のツリー）と「タスク詳細」を切り替える。
  Inboxに入った時は紐付け先。行の選択だけでは詳細へ切り替えない（Enter・行のメニューの「詳細を表示」・タブで切り替える）。
  ドロップ先はマイルストンだけ（プロジェクト自体・マイルストン0件のプロジェクト・完了済み・削除済みは不可）。同名は区別して表示する。
- Inboxの複数選択: 単一選択・⌘+クリック（追加・解除）・Shift+クリック（表示順の範囲）。キーボードは Shift+↑↓・X・⌘A・Esc。
  一括操作は表示中の選択タスクだけ（絞り込みで外れたIDは選択から外す）。仮想化では選択を失わない。選択件数を表示する。
- Inbox → マイルストンのドラッグ＆ドロップ（選択中の行なら選択集合、未選択の行ならその1件）。ドラッグ中は件数・ドロップ先・不可の理由を示す。
  Esc・領域外では保存しない。キーボードは既存の紐付けメニュー（M）で複数をまとめて紐付ける。
  保存は Main の一括API（1つのトランザクション。1件でも条件を満たさなければ全体を変更しない）。成功したら Inbox から除き、
  右詳細に表示中なら選択を解除する（「この一覧の対象外です」の表示を出さない）。失敗時は行・選択を残し理由を表示する。
- タスクの削除（Inbox・Project）: 確認ダイアログを出さずに物理削除する。Inboxは選択中の複数を一括削除できる（Main の1つのトランザクション）。
  文字入力中の Delete／Backspace では削除しない。削除するタスク自身の未保存タイトルは確認なしで破棄する。他タスクの未保存入力・終了時の確認は維持。
  マイルストン・プロジェクトの削除確認は変えない。ゴミ箱・Undo・論理削除は追加しない。
- タスク名のインライン編集（Inbox・カード）: ダブルクリック・F2・行のメニュー。Enter・blurで保存、Escで取り消し（IME変換中のEnterでは保存しない）。
  空は保存しない、変更なしは保存しない（updatedAt を変えない）。既存のタイトル保存（保存キュー）と未保存の確認（DraftGuard）に統合。
- Project内のタスクの順序: 初期は各マイルストン内で作成日時の古い順（同時刻はIDの昇順）。行の先頭のハンドルか Alt+↑↓ で同じマイルストン内を並べ替え、
  手動順として保存する（再起動後も復元。新規・移動したタスクは手動順があれば末尾）。並べ替えの設定に「手動順」（既定）と「作成日時が古い順」などを用意。
  検索あり・状態が「すべて」以外では並べ替えを無効にし、理由を示す。並べ替えで作成日時・完了日時は変えない。カード間の移動は追加しない。
- マイルストンカードの順序: 見出しのハンドル（ドラッグ・キーボード）で並べ替え、プロジェクト単位で保存する。NEW MILESTONE は常に末尾。
- カードのレイアウト column／row（トップバー。Project 画面共通のUI設定として保存。初期値 column）。row ではカードを縦に並べ、幅のハンドルは出さない
  （column 用のカード幅は保持する）。
- 終了: 最後のウィンドウを×で閉じたら、保存確認を通って macOS でもアプリを終了する。開発起動（npm run dev）では、その起動の
  Electron・開発サーバー・electron-vite を残さない。Ctrl+C（SIGINT）・⌘Q も同じ保存確認を通る。キャンセルなら残す。

## 期限と Summary Review（フェーズ6。2026-11-11 ユーザーの指示）

  各セクションは期限 → 作成日時 → ID の順。0件でも見出しを残し「該当なし」。大きなタイトル・操作説明・独自の操作は追加しない。
  トップバーの表示設定は出さない。ステータスバーの中央に3セクションの合計件数。初期表示の画面は変えない。
- 期限の設定の入口は、次の「共通のタスク行」で行の期限表示（未設定なら期限設定アイコン）に移した（行のメニューの「期限 ›」は廃止）。

## 共通のタスク行（TaskRow）とお気に入り（2026-11-11 ユーザーの指示）

- Summary Review の各セクション・Inbox の一覧・プロジェクトのマイルストンカードの行を、共通の TaskRow に置き換える（画面ごとに複製しない）。
  取得条件・選択集合・セクション・カード構成は各画面に残す。
- 2行構成: 1行目（左寄せ）完了チェックボックス・タスク名、2行目（右寄せ）お気に入りの星・期限（未設定なら期限設定アイコン）・紐付けアイコン・「…」。
  作成日時は表示しない（データ・初期の並べ替えは変えない。Inbox の「作成日時」での並べ替えは残す）。長い名前・狭いカード幅でも重ねない。
- 完了チェック: 既存の完了状態（completed_at）と完了API。done 列は追加しない。チェックでモーダルを開かない。Summary では完了の保存後に外す。
- お気に入り: tasks に favorite（論理型・NOT NULL・既定 false。既存タスクも false。0009）。星（true: 黄色の塗りつぶし、false: 白抜きの淡い星）を押すと切り替え。
  aria-pressed・アクセシブル名・ツールチップ。保存失敗は理由を表示し、表示を保存済みの値に戻す。連打しても最後の状態を保存する。
  お気に入り順の並べ替え・専用画面は作らない。
- タスク名: シングルクリックでタスク編集モーダル（3画面共通。中身は詳細パネルと同じ TaskEditor）。ダブルクリックはその場のインライン編集
  （モーダルを先に開かない）。Inbox の ⌘／Shift 付きクリックは複数選択（モーダルを開かない）。行の背景のクリックは従来どおりの選択。
  モーダルを開いても右の詳細は開かない。キーボードは E（モーダル）・F2（インライン編集）。
- 期限: 既存の dueto。ローカルの暦日の差で Today／Tomorrow／{N}Days（明後日は 2Days）。昨日以前は日付そのもの（期限超過と分かる見た目・読み上げ）。
  期限表示・期限設定アイコンを押すと Today／Tomorrow／日付指定…／期限を解除（設定済みのみ）。キーボードは D。
- 紐付けアイコン: Inbox の紐付けと同じアイコン（文字なし・ツールチップあり）。既存の紐付けメニュー（Project › Milestone を選び最終選択で1回だけ保存）。
  Inbox のタスクは Inbox からの紐付け、プロジェクト所属のタスクは単体の所属変更（Summary・プロジェクト）。その行の1件だけ。キーボードは M
  （Inbox は従来どおり選択中のタスクの一括紐付け）。所属の変更だけでは Summary から外さない。
- 「…」: 項目は「削除」だけ（確認なし・その行の1件）。Inbox の一括削除（選択バー・Delete キー）は維持。キーボードは Shift+F10 / ContextMenu。
- お気に入りはキーボードの F。Summary Review に新しいドラッグ操作は追加しない。

## UI状態の保存案

- 選択中のアクティビティ
- 左右ペインの幅
- 詳細パネルの表示状態
- 開いているタブ
- アクティブタブ

保存は業務データと分離する。
ドラッグ中の毎フレームのDB書き込みは避ける。

## 初期版の対象外

明示的な追加依頼がない限り、以下を前提にしない。

- クラウド同期
- 複数端末同期
- アカウント・ログイン
- チーム共有
- プラグイン機構
- VS Code拡張API互換
- モバイル版
- カレンダーや外部サービスとの連携

## 要確認事項

- アプリ名、アプリID
- ペイン配置ライブラリ
- タブ分割・ドラッグ移動の必要性
- DBドライバーとORM
- タスク階層・プロジェクト階層
- Next Actionsの判定条件
- 期限と開始日、繰り返しの仕様
- バックアップの保存先と保持数
- 配布対象CPU、署名・公証の必要性
