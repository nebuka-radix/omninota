# 要件

## 目的

macOS向けに、VS Code風の操作感を持つGTDツールを開発する。
ローカルSQLiteファイルにデータを保存する。

## 明示された要件

- macOS、VS Code、Electron、TypeScriptを使用する。
- Claude Codeで開発を進める。
- データはSQLiteファイルへ永続保存する。
- TanStack Query、Table、Virtual、Routerを採用する。

## ここまでの構成案

- ReactをUI基盤とする。
- MUIをUIコンポーネントに使用する。
- Lucideをアイコンに使用する。
- Motion for Reactをアニメーションに使用する。
- Main、Preload、Rendererを分離する。
- 単一リポジトリ、単一package.jsonから始める。

上記は会話上の構成方針。
厳密な承認状況はtechnology-decisions.mdを参照する。

## 画面構成案

- トップバー
- アクティビティバー
- 左サイドバー
- メインパネル
- 右詳細パネル
- ステータスバー

基本はダークテーマとし、カードよりリストとペインを優先する。

## GTD機能の候補

初期の縦断実装:
- Inboxへのタスク追加
- タスク一覧
- タスク詳細の表示・編集
- タスク完了
- 再起動後のデータ復元

後続の機能候補:
- プロジェクト
- Next Actions
- 待機中
- いつか／たぶん
- 期限・タグ
- 完了履歴
- 週次レビュー
- 検索・絞り込み

後続機能の詳細ルールは、実装前に決める。

## UI状態の保存案

- 選択中のアクティビティ
- 左右ペインの幅
- 詳細パネルの表示状態
- 開いているタブ
- アクティブタブ

保存は業務データと分離する。
ドラッグ中の毎フレームのDB書き込みは避ける。

## 初期版の対象外

明示的な追加依頼がない限り、以下を前提にしない。

- クラウド同期
- 複数端末同期
- アカウント・ログイン
- チーム共有
- プラグイン機構
- VS Code拡張API互換
- モバイル版
- カレンダーや外部サービスとの連携

## 要確認事項

- アプリ名、アプリID
- ペイン配置ライブラリ
- タブ分割・ドラッグ移動の必要性
- DBドライバーとORM
- タスク階層・プロジェクト階層
- Next Actionsの判定条件
- 期限と開始日、繰り返しの仕様
- バックアップの保存先と保持数
- 配布対象CPU、署名・公証の必要性
